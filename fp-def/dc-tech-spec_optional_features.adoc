ネットアップは、 FlexPod データセンターのアーキテクチャをさらに強化するために、いくつかのオプションコンポーネントをサポートしてオプションコンポーネントについては、以降のサブセクションで説明します。


NOTE: SAN ブートはオプションですが、ハードウェアのアップグレードや交換時にサーバー プロファイルを移動できるため、強く推奨されます。



[[iscsi-boot-option]]
== iSCSI ブートオプション

iSCSIブートオプションの最小要件は以下のとおりです：

* ネットアップストレージコントローラでアクティブ化された iSCSI ライセンス / 機能
* ネットアップストレージコントローラ HA ペアの各ノードに、 2 ポート 10Gbps イーサネットアダプタを搭載します
* iSCSI ブートに対応した Cisco UCS サーバ内のアダプタ


以下の図は、IPベースのiSCSI構成向けのXシリーズモジュラーシステムとCシリーズラックサーバーを備えたFlexPod データセンターの例を示しています。

image:dc-tech-spec_image15.png["FlexPod IPベースのiSCSI接続のためのデータセンター"]

この構成の詳細については、link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod データセンター（Cisco UCS M7 IMM、VMware vSphere 8.0、NetApp ONTAP 9.12）設計ガイド"^]を参照してください。



[[fc-boot-with-cisco-mds]]
== Cisco MDSを使用したFCブート

専用SANネットワークを使用することで拡張性を向上させるため、FlexPod は Cisco MDS スイッチを通じて FC をサポートしています。Cisco MDS を経由した FC SAN ブートオプションには、以下のライセンスおよびハードウェア要件があります：

* ネットアップストレージコントローラごとに少なくとも 2 つの FC ポート。 SAN ファブリックごとに 1 つのポート
* 各 NetApp ストレージコントローラのFCライセンス。
* FC ブートに対応した Cisco UCS サーバーのアダプター。


次の図は、MDSスイッチを使用したFCベースのSAN構成向けに、XシリーズモジュラーシステムとCシリーズラックサーバーを備えたFlexPod データセンターの例を示しています。

image:dc-tech-spec_image16.png["FlexPod FCベースのSAN接続に対応したデータセンター"]

この構成の詳細については、link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod データセンター（Cisco UCS M7 IMM、VMware vSphere 8.0、NetApp ONTAP 9.12）設計ガイド"^]を参照してください。

[[end-to-end-fc-nvme]]
== エンドツーエンドの FC-NVMe

エンドツーエンドFC-NVMeは、お客様の既存のSANインフラストラクチャをリアルタイムアプリケーション向けにシームレスに拡張しながら、同時にIOPSとスループットを向上させ、レイテンシを低減します。既存の32G FC SANトランスポートを使用することで、NVMeとSCSIの両方のワークロードを同時に転送できます。

この構成の詳細については、link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod データセンター（Cisco UCS M7 IMM、VMware vSphere 8.0、NetApp ONTAP 9.12）設計ガイド"^]を参照してください。



[[cisco-ucs-x-series-direct-and-direct-attached-aff-asa-fas-for-fc-and-ip-based-san]]
== Cisco UCS X シリーズ ダイレクトおよびダイレクトアタッチ AFF/ASA/FAS の FC および IP ベースの SAN 向け

NetAppストレージコントローラは、上流のSANスイッチを必要とせずに、Cisco UCSファブリック インターコネクトに直接接続できます。FlexPodは、UCS X-Series DirectでFCおよびiSCSIブートの両方をサポートします。

ライセンスとハードウェアの要件は次のとおりです。

* ネットアップストレージコントローラにはプロトコルライセンスが必要です。
* サーバーには Cisco UCS アダプタ（イニシエータ）が必要です。サポートされている Cisco UCS アダプタの一覧については、NetApp https://imt.netapp.com["IMT"^]を参照してください。
* ネットアップストレージコントローラにはターゲットアダプタが必要です。


次の図は、IPベースSAN向けのUCS X-Series Directおよび直接接続されたASAトポロジーを示しています。

image:dc-tech-spec_image13.png["UCS X-Series ダイレクトおよびダイレクトアタッチ ASA IPベース SAN のトポロジー"]

* Cisco UCS はイーサネットスイッチングモードで設定されます。
* ターゲットからファブリックインターコネクトへの iSCSI ポートは、 iSCSI データ用のイーサネットストレージポートとして構成されます。


次の図は、IPベースおよびFCベースのSAN向けのUCS X-Series DirectおよびASA直接接続トポロジーを示しています。

image:dc-tech-spec_image14.png["UCS X-Series ダイレクトおよびダイレクトアタッチ ASA の IP ベースおよび FC ベースの SAN トポロジー"]

この構成の詳細については、 https://www.netapp.com/pdf.html?item=/media/135828-flexpod-san-ucs-xdirect-asa-nva-deploy-guide.pdf["Cisco UCS X-Series DirectおよびNetApp ASAを使用したFlexPod SAN解決策"^]を参照してください。

[[metrocluster]]
== MetroCluster

FlexPod MetroCluster IP with VXLAN マルチサイトファブリックソリューションは、2つのサイトに配置された2つのFlexPodsで構成されており、一定の距離を隔てていますが、接続されてペアリングされることで、サイト障害が発生してもビジネス継続性を提供できる、可用性、柔軟性、信頼性に優れたデータセンターソリューションを実現します。サイト間の最大サポート距離は約435マイル（700km）です。

FlexPod MetroCluster IPソリューションでは、Cisco VXLANマルチサイトソリューションを使用することで、地理的に分散した複数のデータセンターに展開されたVXLANファブリックを相互接続し、一元的に管理できます。NetApp MetroCluster IPは、2つのNetAppストレージクラスタ間の同期レプリケーションソリューションを提供し、キャンパスや都市圏においてストレージの高可用性とディザスタリカバリを実現します。このソリューションにより、分散統合インフラストラクチャ上にVMware vSphereベースのプライベートクラウドを設計し、複数のサイトが単一サイトとほぼ同じように動作できる統合ソリューションを提供すると同時に、完全なサイト障害を含むさまざまな単一障害点シナリオからデータサービスを保護することができます。

次の 2 つの図は、 VXLAN マルチサイトファブリックと、解決策 IP FlexPod MetroCluster と VXLAN マルチサイトファブリック導入のための MetroCluster IP ストレージファブリックを示しています。

* FlexPod MetroCluster IP 解決策用の VXLAN マルチサイトファブリック


image:dc-tech-spec_image11.png["FlexPod MetroCluster IP 解決策用の VXLAN マルチサイトファブリック"]

* FlexPod MetroCluster IP 解決策用の MetroCluster IP ストレージファブリック

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== SnapMirror アクティブ同期ソリューション（FlexPod MetroCluster IP ソリューション向け）

NetApp ONTAPソフトウェアのNetApp Snapshotテクノロジを使用することで、ミッションクリティカルなSANデータサービスをSnapshotベースのバックアップのデータから迅速に復旧できます。

* 2つの異なるサイトに展開された2つのONTAPクラスタは、同期データレプリケーションとディザスタリカバリのために、ピアリングされ、SnapMirrorアクティブ同期で設定されています。
* ONTAP メディエーターは、下図に示すように、第 3 障害ドメインに展開されます。クラスターとともに、ONTAP メディエーターはSnapMirrorアクティブ同期ソリューションのクォーラムを完成させます。
* ONTAP メディエーターは、ピアリングされた ONTAP クラスタとノードからヘルス情報を受け取り、それらの間を調整してステータスを判断します。ヘルスデータは、クラスタがさまざまな種類の障害を区別し、自動フェイルオーバーを実行するかどうかを判断するのに役立ちます。


image:dc-tech-spec_image18.png["SnapMirror アクティブ同期ソリューションコンポーネント（FlexPod MetroCluster IP ソリューション）"]



[[symmetric-active-active-multi-path-support-for-flexpod-metrocluster-ip-solution]]
=== FlexPod MetroCluster IPソリューションの対称アクティブ / アクティブマルチパスサポート

ホスト/クライアントが複製された LUN を使用できるようにするには、リモート クラスタで igroup を作成し、複製された LUN を対応する igroup に割り当て、ホスト/クライアントがiSCSIターゲットとリモート クラスタから利用可能な LUN を追加パスとして見つけられるように設定します。

下図に示すように、エンタープライズアプリケーションは、サイト間の同期データレプリケーション用に設定された 2 つの ONTAP ASA クラスターによってホストされる iSCSI ベースの LUN を使用して、ストレージクライアントに展開できます。図に示す整合性グループには 3 つのアプリケーション固有の LUN が含まれており、データは SnapMirror アクティブ同期によってピアリングされたクラスタに同期的にレプリケートされます。

image:dc-tech-spec_image19.png["SnapMirror アクティブ同期対称アクティブ / アクティブ SAN マルチパス"]

詳細については、 https://community.netapp.com/community/discussion/465452/level-up-flexpod-san-solution-storage-resiliency-with-snapmirror-active-sync["SnapMirror active syncを使用して、FlexPod SANソリューションのストレージ耐障害性をレベルアップします"^]を参照してください。
