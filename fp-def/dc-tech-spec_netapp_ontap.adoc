= NetApp ONTAP
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
NetApp ONTAPソフトウェアは、AFF、ASA、FAS、およびAFXストレージシステム上で動作するオペレーティングシステムです。ONTAPは拡張性の高いストレージ アーキテクチャを提供し、業務の中断を伴わない運用、中断を伴わないアップグレード、および俊敏なデータインフラストラクチャを実現します。ONTAP Oneライセンス モデルにより、すべてのエンタープライズデータサービスが単一のパッケージに含まれるため、導入と管理が簡素化され、高度な機能への完全なアクセスが可能になります。ONTAPは、レプリケーションおよびディザスタリカバリのためのSnapMirrorや、アプリケーション整合性のあるバックアップとリストアのためのSnapCenterなどのテクノロジーを通じて、堅牢なデータ保護を提供します。また、Autonomous Ransomware Protectionや暗号化などの組み込みのセキュリティ機能を備え、最新の脅威からデータを保護します。さらに、ONTAPはSnapMirror CloudやS3ベースのレプリケーションなどの機能によってシームレスなハイブリッドクラウド統合を実現し、一貫性と制御を維持しながらオンプレミスおよびクラウド環境間でのデータ移動を可能にします。

ONTAP の詳細については、 https://docs.netapp.com/us-en/ontap-family/["ONTAP製品ドキュメント"^]を参照してください。

=== マルチパスと論理インターフェース

FlexPod アーキテクチャは、コンピューティング、ネットワーク、ストレージスタック全体でコンポーネントやリンクに障害が発生した場合に高可用性を提供するように設計されています。クライアントアクセスとストレージアクセス用に複数のネットワークパスを用意することで、ロードバランシングとリソース利用率の最適化を実現します。

ONTAPのマルチパスI/Oは、論理インターフェイスを使用して実現されます。LIF（論理インターフェイス）は、ロール、ホームポート、ホームノード、フェイルオーバー先のポートのリスト、ファイアウォールポリシーなどの関連する特性を持つIPアドレスまたはWWPNです。

| NFS / CIFS / S3 | 1. | 2.

[[ontap-snapshot-snapmirror-and-snapcenter]]
=== ONTAP Snapshot、SnapMirror、SnapCenter

スナップショットは、ボリュームの読み取り専用のポイントインタイムイメージです。スナップショットが作成されると、アクティブ ファイル システムとスナップショットは同じディスクブロックを指すため、スナップショットは余分なディスク容量を使用しません。前回のスナップショット作成以降のファイルの変更のみを記録するため、時間の経過とともにイメージが消費するストレージ容量は最小限に抑えられ、パフォーマンス オーバーヘッドもごくわずかです。スナップショットを使用すると、個々のファイルやLUNを復元したり、ボリュームの内容全体を復元したりできます。ONTAPは、スナップショット内のポインタ情報とディスク上のデータを比較することで、ダウンタイムや大幅なパフォーマンス低下を伴うことなく、欠落または破損したオブジェクトを再構築します。

SnapMirrorは、地理的に離れたサイトのプライマリ ストレージからセカンダリ ストレージへのフェイルオーバー用に設計されたディザスタ リカバリ テクノロジです。名前が示すように、SnapMirrorは本番データの複製（ミラー）をセカンダリ ストレージに作成し、プライマリ サイトに災害が発生しても、セカンダリ ストレージから引き続きデータを提供できるようにします。

SnapCenterソフトウェアは、一元化されたシンプルで拡張性の高いプラットフォームです。ハイブリッド クラウド内にあるONTAPシステムで実行されるアプリケーション、データベース、ホスト ファイルシステム、VMで、アプリケーションと整合性のあるデータ保護を実現できます。

レプリケーションおよびディザスタ リカバリのための SnapMirror、アプリケーション整合性バックアップおよびリストアのための SnapCenter などのテクノロジーを活用して、お客様が FlexPod アーキテクチャにデータ保護を組み込むことを推奨します。



[[secure-multi-tenancy]]
=== セキュア マルチテナンシー

セキュア マルチテナンシーとは、共有の物理ストレージ環境内でセキュアな仮想パーティションを使用して、複数の異なるテナント間で物理環境を共有することを目的とした手法です。たとえば、ストレージ サービス プロバイダーは、3 つの異なる顧客それぞれにアレイのディスク容量とネットワーク リソースの一定部分をプロビジョニングするようにストレージ アレイを設定することがあります。セキュア マルチテナント環境では、各顧客は、その顧客に明示的にプロビジョニングされたリソースにのみアクセスできます。顧客は他の顧客のデータにアクセスすることはできず、他の顧客の存在や、共通の物理アレイを共有しているという事実を認識することもありません。セキュア マルチテナント環境では、単一のテナントが共有パフォーマンス能力を過度に消費して他のテナントに影響を与えることがないよう、適切な手段を講じる必要があります。

ONTAPのマルチテナンシーは、ストレージ仮想マシン（SVM）とIPスペースによって実現されます。

ハイパーバイザー上で実行される仮想マシンのように、SVMは物理リソースを抽象化する論理エンティティです。SVMは、1つ以上のボリュームから、1つ以上のネットワーク論理インターフェイス（LIF）を介して、クライアントおよびホストにデータを提供します。

IPspaceを使用すると、単一のONTAPクラスタを設定し、複数の管理上分離されたネットワーク ドメインのクライアントが、たとえ同じIPアドレス範囲を使用している場合でもアクセスできるようにすることができます。これにより、クライアント トラフィックを分離してプライバシーとセキュリティを確保することができます。


NOTE: ONTAP設定に関するFlexPodのベストプラクティスについては、 https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_vvf_9_fc_boot_manual_deploy.html#NetAppONTAPStorageConfiguration["FlexPod CVD：NetApp ONTAPストレージ構成"^]を参照してください。
