= Cisco Unified Edge への ONTAP Select の導入
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
専用の NetApp アプライアンスに代わるソフトウェアで定義されるストレージとして、ONTAP Select はサポートされているハイパーバイザー（KVM または VMware vSphere）上で仮想マシンとして動作し、ローカル接続ストレージを使用して NAS および SAN サービスを提供します。ONTAP Select は、リモートオフィス、バックオフィス拠点、目的に即したエッジ展開、モバイル環境、およびお客様が ONTAP データサービス機能の完全なセットを必要とするその他のシナリオに最適です。


NOTE: ONTAP Select (OTS) on Cisco Unified Edgeは、高可用性（HA）機能を持たないシングルノードインスタンスとしてデプロイされます。

ONTAP Select と Cisco Unified Edge を組み合わせて展開すると、統合されたエッジアーキテクチャが構築されます。ストレージ最適化されたコンピューティングノードが、ローカルの NVMe メディアを提供します。ハイパーバイザーは、適切なリソースを ONTAP Select 仮想マシンに提供します。ONTAP Select は、ローカルメディアを ONTAP アグリゲートおよびボリュームに編成し、同じシャーシ内またはエッジサイトの別の場所でローカルに実行されているアプリケーションワークロードにストレージを公開します。この設計により、データはアプリケーションの近くに保持され、日常業務における WAN 接続への依存度が軽減され、集中管理およびデータ保護の手法にも適合します。

image::ots-on-cue.png[Cisco Unified EdgeアーキテクチャにおけるONTAP Select]

XE130cおよびXE150cコンピューティングノードにおける4台のドライブ制限とソフトウェアRAIDへの依存により、ONTAP Selectの展開は単一コントローラアーキテクチャに限定されます。コントローラのフェイルオーバー機能を備えたマルチノードストレージ アーキテクチャとは異なり、単一のストレージコントローラをコントローラレベルのメンテナンスのためにオフラインにすると、そのコントローラがホストしているローカルストレージサービスに影響が生じます。

この制約はアーキテクチャの価値を否定するものではありませんが、運用モデルに反映させる必要があります。適切なワークロードとは、計画的なストレージ停止に耐えられるもの、アプリケーションレベルの回復力に依存するもの、または中央の ONTAP 環境へのレプリケーションを使用してリカバリを行うものです。お客様は、メンテナンスカレンダーを策定し、サービス提供期間をアプリケーション所有者に伝え、中断を伴う作業を行う前に現在のバックアップまたはレプリカを確認し、ロールバック手順を文書化する必要があります。コントローラーのメンテナンス中にワークロードが継続的なストレージの可用性を必要とする場合、お客様はシングルコントローラーの ONTAP Select 構成ではなく、外部の ONTAP ストレージアレイの導入を検討する必要があります。
